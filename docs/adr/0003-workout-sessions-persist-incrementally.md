# Workout Sessions persist from Start, not written atomically on Finish

Every other domain in this app (Habit Entries, Food Entries, Measurements) is logged as a single atomic insert — the whole record exists or it doesn't. Workout Sessions deliberately break that pattern: a `workout_sessions` row is created as soon as the user taps Start, and each Workout Set is written as its own row the moment it's logged, with a nullable `finished_at` marking completion later. This trades a genuinely new "in-progress" state — something no other table in this schema has — for surviving the app being killed or losing signal mid-workout, a real risk when logging a gym session on a phone, and the one domain here where losing 40 minutes of progress to a crash would actually hurt. Recorded so a future reader doesn't "fix" `workout_sessions` back to the atomic-insert pattern the rest of the schema uses, and doesn't assume every table needs a lifecycle/status column just because this one does.
